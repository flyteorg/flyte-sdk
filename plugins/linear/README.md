# Flyte Linear Plugin

Read and write Linear issues from Flyte tasks, react to Linear webhook events
with an app environment, and expose everything as an MCP server for agents
running on Flyte.

## Installation

```bash
pip install "flyteplugins-linear"            # client only
pip install "flyteplugins-linear[app]"       # + FastAPI app environment
pip install "flyteplugins-linear[mcp]"       # + MCP server
```

## Setup

The plugin reads credentials from environment variables, which on Flyte are
populated by mounting secrets:

```bash
flyte create secret LINEAR_API_KEY --value <api-key>
flyte create secret LINEAR_WEBHOOK_SECRET --value <signing-secret>   # only for webhooks
```

Create a personal API key in Linear under Settings → API → Personal API keys.
The webhook signing secret is generated by Linear when you create a webhook
(Settings → API → Webhooks).

Request the secrets on any task or app environment that needs them:

```python
env = flyte.TaskEnvironment(
    name="linear-demo",
    secrets=[flyte.Secret("LINEAR_API_KEY", as_env_var="LINEAR_API_KEY")],
)
```

## Read/write from tasks

```python
import flyte
from flyteplugins.linear import LinearClient

@env.task
async def summarize_backlog(team_key: str) -> str:
    async with LinearClient() as client:
        issues = await client.list_issues(team_key=team_key, state="Backlog")
    return "\n".join(f"{i['identifier']}: {i['title']}" for i in issues)
```

The client covers teams, workflow states, issues (by `TEAM-123` identifier or
UUID), comments, and issue creation/updates — see
`flyteplugins.linear.LinearClient`. GraphQL errors are raised as
`LinearAPIError`.

## React to Linear events

`LinearAppEnvironment` serves a **setup dashboard** (`/`) and a **webhook
receiver** (`/webhook`). The dashboard walks through API key creation, secret
creation, and Linear webhook configuration; `/api/status` and `/api/verify`
expose machine-readable health.

```python
import flyte
from flyteplugins.linear import LinearAppEnvironment, launch_task

app_env = LinearAppEnvironment(
    name="linear-integration",
    secrets=[
        flyte.Secret("LINEAR_API_KEY", as_env_var="LINEAR_API_KEY"),
        flyte.Secret("LINEAR_WEBHOOK_SECRET", as_env_var="LINEAR_WEBHOOK_SECRET"),
    ],
)

@app_env.on_event("Issue.create")
async def triage_new_issue(event):
    import flyte.remote as remote

    task = remote.Task.get(name="triage_issue", auto_version="latest")
    run = launch_task(task, key=event.dedupe_key(), issue_id=event.entity_id)
    return {"run": run.name}

if __name__ == "__main__":
    flyte.init_from_config()
    flyte.serve(app_env)
```

Webhook payloads are HMAC-verified against `LINEAR_WEBHOOK_SECRET`
(`X-Linear-Signature`), normalized into `LinearEvent` objects, matched against
the optional `team_ids` allowlist, and dispatched to handlers registered with
`on_event` (patterns like `Issue`, `Issue.create`, `Comment.update`; an empty
pattern matches everything).

`launch_task` launches runs **idempotently**: every run carries a `dedupe`
label derived from the event, and a second delivery of the same event raises
`DuplicateRun` instead of launching a second run. Failed or aborted runs never
block, so re-triggering after a failure is a retry.

Create the webhook in Linear (Settings → API → Webhooks) pointing at the app's
public URL + `/webhook`, subscribing to Issues (and Comments if needed).

## MCP server for agents

The read/write surface doubles as MCP tools, so agents running on Flyte can
use Linear through the Model Context Protocol:

```python
import flyte
from flyteplugins.linear import linear_mcp_app_env

mcp_env = linear_mcp_app_env(
    "linear-mcp",
    secrets=[flyte.Secret("LINEAR_API_KEY", as_env_var="LINEAR_API_KEY")],
)

if __name__ == "__main__":
    flyte.init_from_config()
    flyte.serve(mcp_env)
```

The server is **read-only by default** (teams, states, issues, comments). Pass
`read_only=False` to include issue creation, updates, and commenting. Tool
annotations (`readOnlyHint`, `destructiveHint`, `idempotentHint`) are set from
the tool registry. Reacting to events is intentionally *not* an MCP tool —
that is the app environment's job.

Connect an agent running on Flyte:

```python
from flyte.ai.agents import Agent, MCPServerSpec

agent = Agent(
    name="linear-agent",
    mcp_servers=[MCPServerSpec(name="linear", url="https://<app>/mcp/mcp")],
)
```

## Configuration

`flyteplugins.linear.Config` controls API-key/webhook-secret env var names,
the GraphQL endpoint, timeouts, and retries. The module exports
`default_config`; pass a custom `Config` to `LinearClient`,
`build_mcp_server`, or the app environment when you need it.
